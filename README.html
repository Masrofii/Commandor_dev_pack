Features

Telegram Bot

Web Dashboard

Real-Time WebSocket
Emails appear instantly in your dashboard via authenticated WebSocket connections. No polling.

Install as a Progressive Web App on desktop or mobile. Works offline with app shell caching.
🔥
Burner Aliases
One-click 1-hour self-destructing aliases. All emails and attachments deleted at expiry.
🔗
Webhooks
Configurable webhook destinations with HMAC signing, exponential retry, and delivery tracking.
🔑
API Keys
Scoped API keys for external automation. Hashed at rest, shown once, rate-limited, audited.
🌍
Custom Domains
Bring your own domain with server-side DNS TXT verification. Multiple domains per account.
🛡
Spam Scoring
Heuristic spam scoring using SPF/DKIM/DMARC results plus content analysis and sender patterns.
📦
Attachment Security
SHA-256 deduplication, safe filename sanitization, MIME validation, optional ClamAV scanning.
📤
Email Export
Export your inbox as .mbox or .zip of EML files. Background job processing with status tracking.
🔒
Admin 2FA (TOTP)
Admin accounts protected with TOTP two-factor auth including QR enrollment and recovery codes.
🕵️
Tracking Protection
Automatic tracking pixel removal and HTML sanitization. External images blocked by default.
📊
Full-Text Search
SQLite FTS5 powered search with operators: from:, subject:, alias:, before:, after:, is:unread, has:attachment.
🔄
Auto-Reply

Telegram Configuration

🤖 How to get TELEGRAM_BOT_TOKEN

  1. Open Telegram and search for @BotFather
  2. Send /newbot and follow the prompts
  3. Choose a name (e.g. "Commandor Dev Pack") and a username ending in bot
  4. BotFather replies with your token: 123456789:ABCdefGhIjKlmNoPQRsTUvwXyZ
  5. Set: TELEGRAM_BOT_TOKEN=123456789:ABCdefGhIjKlmNoPQRsTUvwXyZ

👤 How to get ADMIN_TELEGRAM_ID (your numeric ID)

  1. Open Telegram and message @userinfobot
  2. It replies: Your user ID: 123456789
  3. Set: ADMIN_TELEGRAM_ID=123456789
VariableRequiredDescription
TELEGRAM_BOT_TOKENRequiredFrom @BotFather — the bot's API token

☁️ How to get Cloudflare R2 credentials

  1. Log in to Cloudflare Dashboard → R2 → Create bucket
  2. Note your Account ID from the R2 overview page (top right)
  3. Click Manage R2 API Tokens → Create API Token
  4. Select Object Read & Write permissions for your bucket
  5. Copy the Access Key ID and Secret Access Key
  6. Set the endpoint: https://<ACCOUNT_ID>.r2.cloudflarestorage.com

Cloudflare Email Worker Setup

ℹ️ Cloudflare Email Routing is free and handles MX routing for you. The Worker forwards raw emails to your backend via HTTPS.

Enable Email Routing in Cloudflare

Cloudflare Dashboard → your domain → Email → Email Routing → Enable. Follow the MX record setup instructions.

Deploy the Worker

cd /opt/commandor-dev-pack/cloudflare

# Login to Cloudflare
wrangler login

# Set secrets (never hardcode these)
wrangler secret put BACKEND_URL
# Enter: https://api.mail.example.com

wrangler secret put INCOMING_SECRET
# Enter: (same value as in your .env)

# Deploy
wrangler deploy

Configure catch-all routing

In Cloudflare Dashboard → Email Routing → Routing Rules → Add rule:
Type: Catch-all → Action: Send to Worker → select your deployed worker.

API Keys

Create scoped API keys for external automation and integrations

✅ API keys are hashed at rest with SHA-256. The raw key is shown only once at creation time.

Available Scopes

ScopeDescription
aliases:readList and view aliases
aliases:writeCreate, update, delete aliases
emails:readList and read emails (body, attachments list)
emails:deleteDelete emails
attachments:readDownload attachments
webhooks:readList webhooks and delivery logs
webhooks:writeCreate and delete webhooks

Creating a Key via API

# First login and get session token, then:
curl -X POST https://api.mail.example.com/api/api-keys \
  -H "Authorization: Bearer YOUR_SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "My Automation",
    "scopes": ["aliases:read", "emails:read"]
  }'

# Response (key shown ONCE — save it now):
{
  "rawKey": "tmk_abc123...",
  "prefix": "tmk_abc123..",
  "scopes": ["aliases:read", "emails:read"]
}

# Use the key:
curl https://api.mail.example.com/api/aliases \
  -H "Authorization: Bearer tmk_abc123..."

curl https://api.mail.example.com/api/emails \
  -H "Authorization: Bearer tmk_abc123..."

Signature Verification

# When a secret is configured, each request includes:
# X-Webhook-Signature: sha256=abc123...

# Verify in Node.js:
const crypto = require('crypto');
function verify(secret, body, signature) {
  const expected = 'sha256=' + crypto
    .createHmac('sha256', secret)
    .update(body)
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(signature)
  );
}

Troubleshooting

# View application logs
pm2 logs commandor-api --lines 100
pm2 logs commandor-web --lines 50
tail -f logs/error-$(date +%Y-%m-%d).log

# Health endpoints
curl -s http://localhost:3000/health | python3 -m json.tool
curl -s http://localhost:3000/ready | python3 -m json.tool
curl -s http://localhost:3000/metrics | python3 -m json.tool

# Database inspection
sqlite3 data/app.db ".tables"
sqlite3 data/app.db "SELECT COUNT(*) FROM emails;"
sqlite3 data/app.db "SELECT COUNT(*) FROM aliases WHERE active=1;"
sqlite3 data/app.db "SELECT * FROM users;"

# Check ports
ss -tlnp | grep -E '3000|3001|80|443'

# Check disk/memory
df -h
free -h

# Restart services
pm2 restart commandor-api
pm2 restart commandor-web
systemctl reload nginx

# Check webhook deliveries
sqlite3 data/app.db "SELECT status,COUNT(*) FROM webhook_deliveries GROUP BY status;"

# Manual backup
npm run backup

# Manual cleanup (dry run)
npm run cleanup:dry

# Check for expired burner aliases
sqlite3 data/app.db "SELECT address,burner_expires_at FROM aliases WHERE burner=1;"
